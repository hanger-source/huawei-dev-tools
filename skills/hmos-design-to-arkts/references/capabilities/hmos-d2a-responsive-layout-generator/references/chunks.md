# 分块生成策略

组件数量较多时，一次性生成完整响应式 DSL 会超出模型输出能力而产生截断。分块生成将长输出拆分为小块，逐块生成后回填合并。

> 本文件只定义分块策略与约束。DSL 的确切数据形状以 `references/dsl-schema.md` 为准；流程口径以能力 `INSTRUCTIONS.md` 步骤 4–6 为准。

## 触发阈值

- 组件数 < 8：单次生成完整 DSL
- 组件数 ≥ 8：分块数 = ⌈组件数 / 7⌉（向上取整）

## 分块原则

- **按布局分组分块**：同一行/同一布局组的组件放入同一块，避免割裂布局语义
- **每块不超过 7 个组件**；某组不足 3 个时与相邻组合并（合并后仍不超过 7 个）
- **骨架**：分块前先在上下文中生成完整嵌套树骨架（仅 metadata、page、layoutStrategy、breakpoints，`ui.children` 为空数组）；骨架作为回填底稿，不单独落盘

## 每块输出约束

- 每块仅输出本块组件的 `responsive` 配置（含 `breakpointOverrides`），不重复输出骨架信息
- 每块必须是合法 JSON，生成后立即做格式验证
- 不同分块的组件 id 不可重复
- `breakpointOverrides` 引用的断点名称必须与骨架中的 breakpoints 一致

## 上下文保持

生成每个分块时，由调用方上下文直接提供：

- 骨架的 layoutStrategy（确保组件 responsive 配置与布局策略一致）
- 容器尺寸信息（用于计算百分比等响应式值）
- 已生成分块的组件 id 列表（避免重复）
- 本块组件在原始输入 DSL 中的绝对位置信息

## 容错与恢复

- 某块生成失败（截断/格式错误）时，仅重新生成该块，不影响已完成的其余分块

## 回填与合并

- 所有分块完成后，按组件 id 将各块 `responsive` 配置回填到嵌套树骨架的对应节点，保持组件在原始 DSL 中的出现顺序
- 同一断点名称的 `breakpointOverrides` 调整合并到该断点下，不得互相覆盖丢失
- 各分块的 warnings / suggestions 去重后追加到最终 DSL 对应字段

**回填验证**：
- [ ] 回填后组件总数 == 原始输入组件总数
- [ ] 所有组件 id 无重复
- [ ] 所有断点引用有效（breakpointOverrides 中的断点名称在 breakpoints 中存在）
- [ ] JSON 格式合法
